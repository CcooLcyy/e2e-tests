# 测试上位机

基于 React + Tauri 的 Windows 本地桌面自动化测试软件。用例和执行内核使用 Python，界面自动发现并列出用例，单任务按顺序执行。环境由用户搭建，自带用例包括登录页校验和正确账号登录，不需要连接下位机；成功登录用例需要可访问的平台和有效测试账号。

## Windows 安装版

测试电脑可使用 Windows x64 安装包。安装包自带 Python 测试内核和固定提交的离线用例。安装版启动后立即从 MskDSPPlatform 查询用例包，之后每 10 秒自动检查，也可点击「刷新用例」。运行中的测试结束并完成清理后，程序会自动启用已准备好的用例包。本体和用例可分别选择 CI 或 Stable。参见[安装版与平台更新](docs/安装版与平台更新.md)和[发布配置](docs/Windows安装包与Stable发布.md)。

## 从仓库启动

运行要求包括 Windows、仓库内准备好的 Python 3.11+ 虚拟环境、WebView2 Runtime 和匹配驱动。从仓库启动时使用仓库中的 Python 内核。

按需构建需要 Node.js 22.12+、Rust 和 Windows C++ 构建工具；准备依赖与驱动需要联网。

```powershell
cd 'C:\storage\repo\dsp迁移\e2e-tests'
git submodule update --init
.\scripts\setup.ps1
.\.venv\Scripts\python.exe start_gui.py
```

环境准备好后，双击仓库根目录的 **启动测试上位机.cmd** 即可使用。启动器会检查源码内容：首次使用或界面、Rust、构建配置有变化时，自动准备 Node 依赖并构建；没有变化就直接打开 Release。只修改 Python 内核或用例不需要编译：内核修改后重新打开测试上位机，用例修改后在界面刷新用例即可。

构建时命令行显示进度；失败会停留并提示原因，不会继续打开旧版本。需要构建时请先关闭已打开的测试上位机。成功记录和日志在本机 local/ 下；首次使用此启动器会构建一次建立记录。只想检查并完成构建而暂不打开界面，可执行 `.\.venv\Scripts\python.exe start_gui.py --build-only`。判定规则详见 [按需构建启动器](docs/按需构建启动器.md)。

Release 程序位于 src-tauri/target/release/mskdsp-testbench.exe，保留在仓库目录中运行。此启动器更新的是测试上位机；测试环境中选择的上位机 exe 仍使用你配置的路径。

开发时可执行 `npm run desktop:dev`，同时启动前端热更新与桌面外壳。

## 使用流程

1. 打开左侧“测试环境”，选择上位机 Release exe 与匹配 WebView2 的 msedgedriver.exe。驱动更新后可重跑 setup.ps1，使用其输出的新路径。
2. 选择运行模式，填写等待时间及结束时是否关闭上位机；截图自动标注默认开启，可在环境中统一关闭，然后保存环境。
3. 用例列表显示当前启用版本的业务用例，勾选本次需要执行的项。
4. 点击开始，观察进度和实时步骤。灰色未执行，绿色通过，红色失败，执行中有动态标记；跳过或停止项保持灰色并注明原因。
5. 点击用例查看业务结果、预期/实际和关键截图。新截图默认展示带编号框和简短说明的标注图，放大后可切换查看原图。完整步骤、原始异常、日志及全部图片通过“诊断资料”查看；历史任务保存在 artifacts 下，可再次查看。
6. 点击停止时先请求取消，必要时清理本次测试工作进程，不会按程序名关闭其他上位机实例。

## slaveSim 管理页

在“测试环境”的“slaveSim 模拟器”中设置完整管理页地址，默认 `http://192.168.1.219:16000`，点击“保存环境”后下次打开会自动回填。地址可留空，已有自定义地址继续保留；旧配置缺少此字段时使用默认地址。

“打开管理页”使用默认浏览器打开当前填写的地址。“检查连接”只读检查 slaveSim 状态接口是否可访问。运行用例时，用例从该入口读取或准备自己的模拟场景，并核对工况是否已生效。子路径代理地址的使用约束见 [slaveSim 管理页地址](docs/slaveSim管理页地址.md)。

运行用例时会按本机系统 Edge 的实际版本自动匹配、缓存或下载 EdgeDriver。该浏览器与 DSP 上位机的 WebView2 独立，报告记录实际使用的浏览器和驱动版本。

## 104 模拟主站

“测试环境”里的“104 模拟主站”默认不启用。启用后选择支持测试会话的新版 `Msk104Master.exe` 和匹配 WebView2 的 `msedgedriver.exe`。曾保存旧主站路径的环境需要重新选择程序。测试使用独立的主站副本与 WebView2 数据目录，检查和运行均由测试上位机启动副本。

“检查主站”可以在保存前执行，仅需要主站和 EdgeDriver 的路径。检查会启动临时副本，确认 EdgeDriver 能读取界面后释放本次资源。模拟主站在端到端用例中用于连接、总召和读取反馈。

“AGC 增减闭锁”和“AGC 通信重分配”需要可确认的专用有功总目标链路。用例当前无法自主确认端点和业务点位，会报告阻塞和未验证项。 [AGC 增减闭锁验收](docs/AGC增减闭锁验收.md) [AGC 通信重分配验收](docs/AGC通信重分配验收.md)

“AVC 周期控制”保留三个验收场景，当前缺少可确认的目标输入链路和逐轮时间证据，定压模式也缺少周期直分配支持。 [AVC 周期控制验收](docs/AVC周期控制验收.md)

## 两种运行模式

界面单次等待默认300秒（5分钟），可在“测试环境 → 等待时间”修改；Modbus采集匹配也默认300秒，环境页允许5至300秒。满足条件后立即继续，不固定等待5分钟。已有环境保留用户保存值，不按默认值强制覆盖；修改保存后，下一次任务使用新值。任务保护按有效步骤进展计时，持续推进的长流程不会因为累计时间长而提前终止；长时间无进展、停止和工作进程异常仍会处理。

- **全新独立副本**：每个用例使用独立 exe 副本和新的运行数据；可显式指定初始配置基线。
- **固定测试工作区**：使用专门的工作区保存副本和数据，重复执行时保留配置，按用例顺序重新打开。工作区不得使用原上位机安装目录，不接管已有用户实例；若选择结束后保留窗口，下一次执行前需要先关闭该测试窗口。

这两种模式控制 DSP 上位机本地程序副本及数据目录的复用。用例根据场景自行准备采集连接、点表和模拟工况。

配置基线读取所选目录顶层的 JSON 配置文件，忽略 `platform-login.json`（大小写不敏感）。固定工作区仅在首次初始化时导入。登录、启动界面和 RTU 用例按用例启动独立副本，即使任务选择了固定工作区也会隔离启动状态。每次运行记录源 exe 的 SHA256。

## 正确账号登录用例

在界面刷新用例，选择“正确账号密码登录成功并进入配置工作台”。本机账号从 `local/login-account.json` 读取，格式为 `{"username": "测试账号", "password": "测试密码"}`；该目录被 Git 忽略，请勿提交真实密码。当前工作机已配置测试账号 `ceshi01`。

用例在独立副本中填写账号密码并提交，通过条件为登录页消失、工作台显示账号信息和“退出”入口，并保存成功截图。账号信息可能显示平台设置的显示名。所测发行版的默认平台须可访问，测试账号须有效。凭据缺失或登录失败会报告失败。

环境默认保存于本机 local/，运行产物保存于 artifacts/；它们均被 Git 忽略。产物保留便于复核，包含副本和 WebView2 数据，会占用磁盘空间。

## 登录记忆与自动登录用例

新增用例覆盖不记住密码、仅记住密码、重开后自动登录、复选框联动、取消记住密码、主动退出、切换账号七项行为。使用真实 Release，通过界面完成设置和登录，在同一用例内正常关闭并重新打开同一测试副本，保留数据目录和 WebView2 数据；不以刷新页面代替重开程序。

这组用例各自启动全新独立副本并准备状态。账号从 `local/login-account.json` 读取，使用所测发行版默认平台的专用账号，无需连接下位机。Windows 密码凭据按平台地址和账号共享，复制 exe 不能隔离凭据。如果该账号已有保存凭据，用例在登录前报告环境问题。正常结束、断言失败及可协作取消时清理本次创建的测试凭据。强制终止可能留下凭据，下次需要人工确认并清理该测试账号的凭据后重试。

报告只记录密码是否为空、是否匹配，不记录密码值。截图保持密码掩码。自动登录后检查工作台账号显示与首次手动登录一致，并核对退出后登录页回填的账号。主动退出登录会关闭自动登录，但保留记住密码，因此“关闭窗口”与“退出登录”分别测试。平台不可达、密码失效等异常登录场景暂不在这批范围内。

开发版修改 `case-suite/` 下的 Python 用例后，在界面刷新列表即可。测试内核变更后重新打开测试上位机。框架自测验证进程生命周期、凭据保护和用例发现，真实登录结果以桌面用例报告为准。

为确保尚未完成的登录请求不会在清理后重新保存密码，这七项用例结束时总是关闭本次测试实例，再清理测试凭据，包括环境选择“结束后保留窗口”的情况。驱动命令日志关闭，防止密码输入和回填值出现在驱动日志中；业务步骤、截图、应用日志及进程启动记录照常保存。

## 用例分组

用例列表采用可折叠的一级功能分组：每组标题下直接显示本组用例，默认收起，支持逐组展开／折叠和“全部展开／全部折叠”。标题前的复选框可整组选中或取消，部分选中时显示半选，标题显示总数、已选数和通过／失败数。搜索匹配分组、名称和说明，并自动展开匹配项，清空搜索后恢复原展开状态。折叠和搜索不改变勾选，表头复选框选择当前搜索结果（包含已折叠的匹配项），分组复选框始终作用于完整分组。

当前依次执行基础登录（3 项）、启动与界面（1 项）、密码记忆与自动登录（7 项）、Modbus RTU（7 项）、AGC 增减闭锁（5 项）、AGC 通信重分配（1 项）、AVC 周期控制（3 项），每组内按登记顺序执行。分组和组内顺序由 `tests/case-order.json` 明确维护，界面编号、任务记录和实际执行一致。首次加载默认勾选全部用例，刷新会保留已有选择和展开状态。新分组默认收起，运行期间选择锁定，仍可展开和折叠查看。

新增文件可声明 `pytestmark = pytest.mark.case_group("分组名称")`；单项用例也可用 `@pytest.mark.case_group("分组名称")` 覆盖文件默认值。新增用例还须在 `tests/case-order.json` 对应组的 `cases` 列表末尾登记完整用例标识，新分组追加到 `groups` 列表末尾。未标记的旧用例显示为“未分组”，非法分组或顺序清单会明确报错。搜索、折叠和勾选先后均不改变执行顺序。详细规则见 [用例分组设计](docs/用例分组设计.md)。

## 添加用例

在用例仓库的 `tests/` 中新增 `test_*.py`，编写 `test_` 开头的函数。函数文档字符串用简短中文写明验证目标，作为用例标题。通过 `@execution_logic` 按实际顺序写明初始状态、关键操作、观察点和通过条件，显示在「执行详情 → 执行逻辑」。pytest 参数实例独立显示。用例和场景辅助代码提交到用例仓库，安装版从平台刷新。只有本体发版需要更新随附用例时，才更新这里的 `case-suite` 子模块指针。 [用例仓库](https://github.com/CcooLcyy/e2e-test-cases)

登录类、启动与界面及 Modbus RTU 用例使用 `case_plan` 编排可执行步骤。执行器按清单运行，「执行详情 → 测试流程」逐项显示待执行、运行中和最终状态，历史详情保留本次步骤清单。协议用例复用公共登录流程。华为机群按工况列出每台设备的检查，点位明细和准备、清理的技术细节仍可在诊断资料中查看。

其他用例使用 `@pytest.mark.case_flow(("操作一", "预期结果一"), ("操作二", "预期结果二"))` 声明计划流程。共用步骤可复用同一组元组，参数实例也可分别声明。用例当前缺少执行前置条件时，用 `blocked="缺失的前置条件"` 说明原因。实际执行结果以用例记录为准。

```python
from case_support.case_metadata import execution_logic


@execution_logic("""
    1. 通过桌面测试夹具打开 DSP 上位机。
    2. 读取当前窗口标题，确认标题为 MskDSP Upper，并保存界面截图。
""")
def test_expected_output(desktop):
    """工作台窗口标题"""
    with desktop.step("检查结果"):
        actual = desktop.driver.title
        desktop.check("窗口标题", actual, "MskDSP Upper")
        desktop.capture("result", description="业务结果页面及窗口标题",
                        expected="窗口标题为 MskDSP Upper", actual=f"窗口标题为 {actual}")
```

desktop fixture 负责运行环境、Selenium 会话、清理及本用例报告。每个操作和检查分别记录：输入账号、输入密码、点击选项、提交、等待页面等使用独立的 desktop.step()；desktop.check() 自动记录检查步骤、预期和实际并断言。每个步骤完成后框架自动截图，失败时立即保留现场；嵌套步骤和同名步骤分别编号，报告步骤表提供对应截图链接。程序未打开、已关闭或截图失败时明确记录证据缺失原因，不补开窗口伪造现场，也不覆盖原业务错误。用例仍可调用 desktop.capture() 补充业务画面及说明。通过、跳过或停止时不额外补拍用例结束图；截图判定来自记录的检查，不能仅凭图片宣称业务通过。详见 [截图与用例报告](docs/自动截图与用例报告.md)。登录、协议配置等新业务动作可逐步封装复用。故障日志用于定位，业务通过条件应基于系统外部可观察的结果。

每项用例使用独立产物子目录，任务保存实时事件、汇总和 JUnit 报告。测试失败不会伪装成成功，独立后续用例仍会执行。
