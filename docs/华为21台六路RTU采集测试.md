# 华为21台六路 RTU 采集测试

## 已确认目标

测试上位机通过真实界面创建 slaveSim 华为行为模型：六路 RS485 依次含 1、2、3、4、5、6 台，共21台；随后在 DSP 上位机创建对应站号的 RTU 连接与点表，逐台核对三相电压、电流、有功、无功、功率因数及发电、停机、待机状态。Modbus TCP 不进入本组。

每个点按“总线、站号、寄存器地址、Tag、类型、字序、倍率”关联。两端值均从真实页面读取；模拟器原始值独立换算为工程量，不从上位机当前值反推预期。通过条件包括数值匹配、质量正常和有效采集时间，不能只检查连接成功。

## 环境与隔离

用户准备测试用 slaveSim、在线下位机、平台测试账号和匹配的浏览器驱动，使用全新上位机副本。环境页仅填写 ModuleManager、当前 DSP 对接的 slaveSim 管理地址以及测试等待参数，不再要求填写六条串口路径或勾选专用模拟器声明。

执行时先读取整个专用模拟器的当前实际配置，初始配置、数量、总线、站号及模型信息留档。通过页面直接删除全部已有总线（包括空总线），连同其下全部从站及点表一并删除，独立保存并应用零总线配置。重新读取保存后的配置，并等待新的运行页面反馈确认零总线、零设备，之后才开始创建；不复用已有机群。删除、保存、读回或零台运行确认失败时停止并保留两端现场，不跳过清空步骤。使用本用例即会删除指定测试模拟器原有总线、从站及点表并释放PTY与软链接，不自动恢复，管理地址须指向专用测试实例。

零台检查通过后，通过模拟器页面从头创建六路1至6台华为模型，采用页面实际提供的默认串口路径，保存并读回确认恰好21台及运行生效。具体规则见 [RTU运行时模拟器配置](RTU运行时模拟器配置.md)。实际软链接须对下位机可见，不通过猜测路径绕过配置发现，也不部署服务。

须使用支持保存零总线配置的slaveSim版本。两种上位机工作区模式仅影响本地程序副本和数据，不隔离或清空远端配置；本用例仍要求全新独立副本。保存模拟器配置会重建运行状态，清空前后及新建前后记录均留档。目标串口已被DSP连接使用时保留前置失败，不接管未知连接。新增模型和本例DSP连接在结束时保留供检查；重复运行时自动删除全部模拟总线，DSP连接占用仍须处理。基础采集的手动原值仍按原流程恢复。本批不读取独立 `local/huawei-rtu.json`。

## 完整执行步骤

1. 从测试上位机选择 RTU 分组中的“华为六路21台完整流程”，读取当前任务环境；要求全新独立副本、有效的 ModuleManager 地址、slaveSim 管理地址和等待参数，并加载测试账号。
2. 启动本例独立的 DSP 上位机副本及 Edge 管理页，等待 slaveSim 页面出现新的运行状态刷新；通过 DSP 上位机登录平台并打开目标下位机。
3. 打开 slaveSim 配置页，重新读取并保存初始配置及数量证据；点击一次“删除全部总线”清空全部总线草稿（包括空总线），确认草稿无总线，然后独立“保存并应用”零总线配置。重新读取确认配置无总线，并等待新的运行反馈确认零总线、零设备；原本无总线也须核对新运行反馈。旧页面缺少该按钮时明确要求更新，不回退为逐条删除。任一步骤失败都停止并取证，不开始创建模型或DSP连接。
4. 确认零台后生成本次唯一总线名称；逐路新增六条总线，读取页面提供的实际串口软链接路径，不自行推测路径。六路依次添加1、2、3、4、5、6台华为V3行为模型，站号分别为1至该路设备数。
5. 对全局第n台（n=1～21）设置直流可用功率10+n kW、线电压380+n V、频率50 Hz、环境温度25℃、效率1，并关闭轻微扰动。每台保持可区分的场景，便于识别串路、串站。
6. 保存前检查六条路径未被DSP已有连接占用；读取草稿，检查21台的有功、视在及无功能力能够满足全部固定工况。失败则保留失败，不改变工况目标。
7. 通过页面“保存并应用”六路21台配置，等待页面确认；读取每台新的运行反馈并核对实际串口路径。重新读取保存后的配置，确认恰好六路总线、21台从站，再核对机群运行路径。
8. 再次检查DSP串口路径占用，并核对已创建机群运行状态；不重复创建机群。
9. 逐路逐站通过DSP上位机创建21条 Modbus RTU 连接：使用实际串口路径、本站站号、9600/8/N/1和环境中的轮询周期。
10. 每条连接添加18个采集点、3个写点，共441点。配置协议地址、类型、寄存器数、倍率、偏移、字节序，BOOL配置状态位，32位量使用HL/AB。
11. 每条连接配置后离开并重新进入，逐项读回连接参数及全部21个点位配置，确认保存正确，再启动该连接的采集功能。确认完整配置21台后进入工况验收。
12. 按下表顺序执行七个工况。每个工况都按第1至6路、每路站号从小到大的顺序遍历21台；先对该台通过slaveSim页面应用本工况，再立即验收该台，然后处理下一台。

| 顺序 | 工况 | 页面操作及主要预期 |
| --- | --- | --- |
| 1 | 发电 | 使用刚创建的初始场景，效率1；P达到10+n kW，Q=0，PF=1。 |
| 2 | 有功调节 | 设置有功百分比10+n/10%；P达到该台有功容量×设定比例，Q=0，PF=1。 |
| 3 | 无功调节 | 设置PF=0.9；保持上一步有功限值，Q为正，PF接近0.9。 |
| 4 | 负无功调节 | 设置Q/S=-0.2；保持有功限值，Q和PF均为负。 |
| 5 | 待机 | 设置直流可用功率0；P=Q=三相电流=0，PF=1。 |
| 6 | 限电停运 | 恢复该台直流可用功率，再设置有功百分比0；P=Q=三相电流=0，PF=1。 |
| 7 | 恢复发电 | 设置Q/S=0、有功百分比100%；恢复初始发电目标、Q=0、PF=1。 |

13. 每台每工况选中对应DSP连接，依次读取“模拟器前采样 → DSP全部18个采集点 → 模拟器后采样”；核对总线、站号、实际路径及新刷新，确认模拟器前后原始值稳定。
14. 从模拟器原始字节独立解码和换算，逐点核对DSP值、地址、功能码、数据类型、正常质量和有效时间；值变化的点还要求时间更新。独立检查固定工况目标、设备状态枚举和状态字，不能仅凭两端值相同通过。
15. 界面单次等待及每台每工况采集匹配均默认300秒（5分钟，采用环境设置），满足条件立即继续；采集等待期间仅重新观察，不重复发控制或修改场景。超时、取数失败、工况错误、点位错误或关键截图缺失均保留失败；可独立继续的设备继续采集证据。
16. 每台每工况保存两端截图、逐次采样及逐点对照，持续更新专项Markdown/JSON报告；正常完整执行应产生147项设备工况、2646项逐点匹配。
17. 全部21台、全部七工况、每工况18个采集点均通过才判定全部抄通。结果只覆盖模拟器发起调节后的DSP采集；3个DSP写点只验收配置，不执行DSP下发控制或104遥控，40200/40201启停单列未实现、未验证。
18. 结束时关闭本例Edge；DSP上位机按环境中的关闭设置处理。保留新建机群、DSP连接、点表及全部证据，不在结束时清空机群、不恢复已删除的原从站。下一次运行再次执行自动清空和实际零台确认。

## 固定验收规则

每台共21点，21台共441点；18个读点在七个工况下形成147项设备工况、2646项逐点匹配。用例作为 RTU 分组中的一项完整业务流程，设备工况在步骤和专项报告中逐项展示，不依赖其他用例先执行。

| 点位 | 协议地址（零基） | 类型／寄存器数 | 倍率／解析 |
| --- | --- | --- | --- |
| A/B/C相电压 | 32069/32070/32071 | UINT16/1 | 0.1 V |
| A/B/C相电流 | 32072/32074/32076 | INT32/2 | 0.001 A |
| 有功／无功 | 32080/32082 | INT32/2 | 0.001 kW/kvar |
| 功率因数 | 32084 | INT16/1 | 0.001 |
| 状态字／设备状态 | 32000/32089 | UINT16/1 | 原始值 |
| 发电／停机／待机 | 32000 | BOOL/1 | bit1/bit7/bit0 |
| 有功／无功模式 | 35300/35304 | UINT16/1 | 原始值 |
| 最后有功／无功指令地址 | 35303/35307 | UINT16/1 | 原始值 |
| 有功百分比设定 | 40125 | UINT16/1，0x06写点 | 0.1% |
| PF／Q-S设定 | 40122/40123 | INT16/1，0x06写点 | 0.001 |

单位是目录和报告的单位说明，当前上位机点位表单没有独立单位字段，不声称向表单保存了单位。

- 固定使用华为 V3 行为模板，不使用普通固定点表代替；关闭轻微扰动，给每台设备设置可区分的电压与可用直流功率，确保可以发现串路、串站。
- 点表至少包括三相相电压、三相相电流、有功功率、无功功率、功率因数、运行状态及三个状态 BOOL，并配置模型支持的有功/无功控制点。32位电流与功率按 HL/AB 解析，有符号 Q 与 PF 不得按无符号读取。
- 原始值按寄存器类型和字节序再次解码，与模拟器页面当前值交叉确认。电压倍率0.1、电流0.001、有功和无功0.001（kW/kvar）、PF倍率0.001。数值误差仅为协议量化分辨率和页面显示精度，禁止用百分比大容差遮蔽错站。
- 每台分别采集模拟器之前/之后两份新反馈，记录上位机观察。模型达到稳态且前后原始值不变时执行严格比较；未稳定或页面过期保持失败，不扩大误差、不重复下发操作。
- 发电工况、有功调节、无功调节以及通过无光照形成的待机、通过有功限值为0形成的限电停运分别核对遥测与状态。限电停运不是40200/40201启停遥控成功。
- 当前模型没有实现40200/40201启停遥控；报告明确列为未实现/未验证，不发送猜测命令，不自动修改模拟器。状态枚举按当前模型约定验收，不代表厂家各固件协议一致。

七个工况依次为发电、有功百分比调节、PF0.9无功调节、Q/S=-0.2负无功调节、无光照待机、百分比0限电停运、恢复发电。给全局第n台设置直流可用功率10+n kW、线电压380+n V、效率1；发电及恢复发电的有功目标为10+n kW。有功调节设定10+n/10%，低于各台可用有功。待机/停运验证P=Q=电流=0，PF=1；恢复工况恢复100%有功与Q/S=0。数值变化的点还检查时间已更新，不要求未变点一定刷新时间。

调节由 **slaveSim 页面**发起，本批验证DSP能抄到实际反馈。三个DSP写点只验证配置保存，DSP下发调节及104遥控路径未执行、未验证，不与采集通过混为一项。

## 证据与失败

每项采样保存总线、站号、点名、地址、Tag、模拟器前后原始值、换算期望、上位机值、差值、质量、时间及两端截图。单点不匹配保留失败并继续采集其他可独立观测点，最后按六路和21台汇总，存在任何失败不得宣称全部抄通。前置条件失败与业务断言失败分开报告。数据变化后还需确认采集时间更新。

默认每台每工况采样等待300秒（5分钟），超过时限后即使值刚匹配也保持超时失败；等待期间只重新观察，不重发场景或控制操作。任务保护按有效步骤进展计时，不按累计总时长截断持续推进的机群用例。采样过程写入 `huawei-samples-*.json`，逐点与逐路结果写入 `huawei-fleet-results.json` 和 `huawei-fleet-results.md`。任一端关键截图保存失败也使工况失败。报告“全部抄通”只覆盖采集和反馈范围，启停及DSP写控制的缺口始终单列。

本次测试流程修改位于测试上位机工程；另经用户单独授权，slaveSim增加保存零从站配置的能力，不修改DSP上位机或下位机。按仓库约定不主动执行本地构建或自动化测试；先补自测与业务用例，再实现页面适配与编排，通过 Git 差异审查后分别提交推送。真实桌面及下位机结果由用户执行本组用例获得；CI 无覆盖时明确说明缺口。
