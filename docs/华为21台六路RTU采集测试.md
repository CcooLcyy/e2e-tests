# 华为21台六路 RTU 采集测试

## 已确认目标

测试上位机通过真实界面创建 slaveSim 华为行为模型：六路 RS485 依次含 1、2、3、4、5、6 台，共21台；随后在 DSP 上位机创建对应站号的 RTU 连接与点表，逐台核对三相电压、电流、有功、无功、功率因数及发电、停机、待机状态。Modbus TCP 不进入本组。

每个点按“总线、站号、寄存器地址、Tag、类型、字序、倍率”关联。两端值均从真实页面读取；模拟器原始值独立换算为工程量，不从上位机当前值反推预期。通过条件包括数值匹配、质量正常和有效采集时间，不能只检查连接成功。

## 环境与隔离

用户准备专用 slaveSim 实例、在线下位机、平台测试账号、匹配的浏览器驱动。六条串口路径由本机忽略配置 `local/huawei-rtu.json` 明确提供，必须在下位机可见；不猜测设备路径，不部署服务。本组使用全新上位机副本。

将[示例](examples/huawei-rtu.example.json)复制至 `local/huawei-rtu.json`，填写实际 ModuleManager 地址及六条共享串口软链接路径（Linux绝对路径，可位于 `/dev` 或共享目录）。示例地址为文档占位值，不能直接视为现场配置。保存测试环境中的 slaveSim 地址，确认 `local/login-account.json` 是专用账号，然后刷新用例列表，选择 RTU 分组末尾的“六路21台华为逆变器自动配置并逐台核对遥测、状态及调节反馈”。不要求旧两站手动点用例的 `local/modbus-rtu.json`。

新增总线与连接均使用本次唯一名称，站号每路从1递增，不接管或覆盖既有总线、设备或连接，路径被占用时前置失败。slaveSim 保存配置会重建全部模型并重置临时状态，因此必须使用专用模拟器。六条路径仅有本批连接轮询。创建的配置与逐台结果均留档；成功和失败后保留本次已创建配置供检查，浏览器只关闭本例实例。重复运行前用户须处理上次保留的测试路径与连接，不自动删除未知资源。

## 固定验收规则

每台共21点，21台共441点；18个读点在七个工况下形成147项设备工况、2646项逐点匹配。用例作为 RTU 分组中的一项完整业务流程，设备工况在步骤和专项报告中逐项展示，不依赖其他用例先执行。

| 点位 | 协议地址（零基） | 类型／寄存器数 | 倍率／解析 |
| --- | --- | --- | --- |
| A/B/C相电压 | 32069/32070/32071 | UINT16/1 | 0.1 V |
| A/B/C相电流 | 32072/32074/32076 | INT32/2 | 0.001 A |
| 有功／无功 | 32080/32082 | INT32/2 | 0.001 kW/kvar |
| 功率因数 | 32084 | INT16/1 | 0.001 |
| 状态字／设备状态 | 32000/32089 | UINT16/1 | 原始值 |
| 发电／停机／待机 | 32000 | BOOL/1 | bit1/bit7/bit0 |
| 有功／无功模式 | 35300/35304 | UINT16/1 | 原始值 |
| 最后有功／无功指令地址 | 35303/35307 | UINT16/1 | 原始值 |
| 有功百分比设定 | 40125 | UINT16/1，0x06写点 | 0.1% |
| PF／Q-S设定 | 40122/40123 | INT16/1，0x06写点 | 0.001 |

单位是目录和报告的单位说明，当前上位机点位表单没有独立单位字段，不声称向表单保存了单位。

- 固定使用华为 V3 行为模板，不使用普通固定点表代替；关闭轻微扰动，给每台设备设置可区分的电压与可用直流功率，确保可以发现串路、串站。
- 点表至少包括三相相电压、三相相电流、有功功率、无功功率、功率因数、运行状态及三个状态 BOOL，并配置模型支持的有功/无功控制点。32位电流与功率按 HL/AB 解析，有符号 Q 与 PF 不得按无符号读取。
- 原始值按寄存器类型和字节序再次解码，与模拟器页面当前值交叉确认。电压倍率0.1、电流0.001、有功和无功0.001（kW/kvar）、PF倍率0.001。数值误差仅为协议量化分辨率和页面显示精度，禁止用百分比大容差遮蔽错站。
- 每台分别采集模拟器之前/之后两份新反馈，记录上位机观察。模型达到稳态且前后原始值不变时执行严格比较；未稳定或页面过期保持失败，不扩大误差、不重复下发操作。
- 发电工况、有功调节、无功调节以及通过无光照形成的待机、通过有功限值为0形成的限电停运分别核对遥测与状态。限电停运不是40200/40201启停遥控成功。
- 当前模型没有实现40200/40201启停遥控；报告明确列为未实现/未验证，不发送猜测命令，不自动修改模拟器。状态枚举按当前模型约定验收，不代表厂家各固件协议一致。

七个工况依次为发电、有功百分比调节、PF0.9无功调节、Q/S=-0.2负无功调节、无光照待机、百分比0限电停运、恢复发电。给全局第n台设置直流可用功率10+n kW、线电压380+n V、效率0.98；有功调节设定10+n/10%，低于各台可用有功。待机/停运验证P=Q=电流=0，PF=1；恢复工况恢复100%有功与Q/S=0。数值变化的点还检查时间已更新，不要求未变点一定刷新时间。

调节由 **slaveSim 页面**发起，本批验证DSP能抄到实际反馈。三个DSP写点只验证配置保存，DSP下发调节及104遥控路径未执行、未验证，不与采集通过混为一项。

## 证据与失败

每项采样保存总线、站号、点名、地址、Tag、模拟器前后原始值、换算期望、上位机值、差值、质量、时间及两端截图。单点不匹配保留失败并继续采集其他可独立观测点，最后按六路和21台汇总，存在任何失败不得宣称全部抄通。前置条件失败与业务断言失败分开报告。数据变化后还需确认采集时间更新。

默认每台每工况采样等待30秒，超过时限后即使值刚匹配也保持超时失败；等待期间只重新观察，不重发场景或控制操作。采样过程写入 `huawei-samples-*.json`，逐点与逐路结果写入 `huawei-fleet-results.json` 和 `huawei-fleet-results.md`。任一端关键截图保存失败也使工况失败。报告“全部抄通”只覆盖采集和反馈范围，启停及DSP写控制的缺口始终单列。

本次只修改测试上位机工程，不修改被测系统。按仓库约定不主动执行本地构建或自动化测试；先补自测与业务用例，再实现页面适配与编排，通过 Git 差异审查后提交推送。真实桌面及下位机结果由用户执行本组用例获得；CI 无覆盖时明确说明缺口。
