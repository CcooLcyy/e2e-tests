# Modbus RTU 到 104 品质验收

本例通过 DSP 上位机创建专用的 RTU 与 IEC104 业务链路，通过 slaveSim 驱动 RTU 工况，由独立的 Msk104Master 会话接收总召和自发遥测。

## 运行环境

使用已给出的 slaveSim 入口、支持独立测试会话的 104 主站、所需 WebDriver 及本机专用平台账号。DSP 上位机必须已有可用的在线业务连接和明确的现场直连主机。用例只读界面显示的现有主机地址，再从正常 IEC104 业务界面读取自己创建的监听端口和公共地址。若当前只提供平台隧道，或主站到本例协议端口不可达，记录对应失败阶段。

slaveSim 当前的「保存并应用」会重建所有从站，包括无关模型及临时值。本例仅在没有无关从站的实例上执行整份配置应用。两路新建的 PTY 路径由模拟器界面分配，DSP 必须能访问这些路径。用例在创建前检查路径未被既有 RTU 连接占用。

## 执行流程

1. 新建两路本例模拟总线。参照总线配置站号 1、保持寄存器 0、固定值 100，目标总线初始不配置从站。
2. 通过 DSP 上位机正常界面创建两条本例 RTU 连接和采集点，分别使用模拟器的实际路径、站号 1、保持寄存器 0、UINT16 及正死区。新建专用 IEC104 Server 被控站、启用带时标上送，从数据总线导入两点为短浮点遥测并创建路由。
3. 启动 IEC104 链路和两条 RTU 轮询，观察参照点为 100，并确认 slaveSim 日志显示目标站未配置而丢弃读请求。主站连接后在同一会话发起一次总召。
4. 总召终止且完成初始点表检查后，依次在目标总线上设置四个工况。每个阶段从 slaveSim 当前应用后的可见报文核对读请求与响应，再等待主站的对应遥测。

| 阶段 | slaveSim 工况 | IEC104 品质 |
| --- | --- | --- |
| 首次有效采集 | 站号 1 的寄存器 0 正常返回 100 | `0x00` |
| 通信超时 | 移除目标从站，已收到的请求无应答 | `0x40` |
| 设备异常响应 | 恢复站号 1，只配置寄存器 1，读取寄存器 0 返回异常码 `0x02` | `0xC0` |
| 同值恢复 | 恢复寄存器 0，正常返回 100 | `0x00` |

## 通过条件

- 主站收到总召肯定确认及终止，期间同 CA 至少有一条正常参照遥测。总召响应和初始自发报文均省略无首值的目标点。
- 总召后同 CA/IOA 的自发短浮点遥测（类型 36，COT=3）保持 100，品质顺序为 `0x00 → 0x40 → 0xC0 → 0x00`。两种故障沿用同一旧样本时标，恢复后时标更新。同品质可重复，故障报文重复时仍须沿用原时标。
- 保留模拟器配置和阶段报文、主站收发报文及解析结果。失败时在删除本例链路与模拟总线前保留现场。无法清理的对象会在报告中记录。
