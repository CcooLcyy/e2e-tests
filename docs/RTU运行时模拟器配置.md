# RTU 用例运行时跟随 slaveSim 配置

## 已确认行为与边界

测试环境仅保存 DSP 的 ModuleManager 地址、当前 DSP 对接的 slaveSim 管理地址、轮询周期及采集等待时限。串口路径、总线、站号、寄存器和模型必须在用例执行时读取 slaveSim 的当前配置，不再要求在环境页重复填写，不再由专用资源确认复选框阻止任务开始。历史环境中的基础采集和华为六路参数兼容保存，但不作为运行时配置来源。

本次修改仅限测试上位机。用例通过 slaveSim 可见管理页面读取和必要时配置模拟器，通过 DSP 上位机可见页面配置本例采集连接；不修改 DSP 或 slaveSim 源码，不部署或操作现场设备。管理地址必须指向当前 DSP 实际对接的模拟器，地址可访问不等于串口已经对接。

## 执行与异常

1. 启动前只检查连接入口、独立副本模式和测试等待参数。
2. 执行时读取模拟器当前已应用配置，保存配置与资源发现证据；按照用例需要选择总线、站号和寄存器。
3. 基础采集缺少适用资源时，通过管理页面补充用例所需资源，保留其他总线、设备和寄存器。华为21台用例必须从零逆变器开始：允许已有空总线，任何已有从站（包括无模型、无法确认类型的静态点表）均报告前置失败，由用户手动清空后重跑；不删除、不复用。检查通过后从头创建六路21台。新总线采用模拟器当前页面提供的实际默认路径，不在测试端拼接或假定六条路径。保存后重新读取配置和运行反馈，确认生效。
4. 基础用例仍验证两个自定义从站、手动 UINT16 / AB / readwrite 保持寄存器；华为用例仍验证六路分别 1 至 6 台、共 21 台模型及原工况和点表。不得为适配已有模型放宽业务断言。
5. 当前 slaveSim 使用 PTY，并无 UART 波特率、数据位、校验位和停止位配置；DSP 本例连接使用 9600 / 8 / N / 1。不能将这些默认参数描述成从 slaveSim 读取到的参数。
6. 发现结果不唯一、路径无效、保存失败、模型不适用或 DSP 无法访问串口时，在相应步骤失败并保留两端现场，区分前置条件和业务验收，不改判通过或跳过。

基础用例维持原值恢复和本例 DSP 连接清理语义；新增模拟资源及华为模型保留供检查。保存模拟器配置可能重建运行状态，必须在步骤日志与报告中记录配置前后及影响。已有失败报告保持原样。

## 验收与验证范围

- 只配置两个连接入口和等待参数时，所选六项 RTU 用例能够进入运行时资源准备阶段；缺失旧静态参数和未勾选旧确认项不再阻止启动。
- 环境内旧串口、站号、寄存器即使与实际不一致，也不能覆盖运行时发现结果。
- 配置不足时有明确的读取、补充、保存、读回确认记录；失败不掩盖且保留证据。
- 原数值换算、质量、采集时间、多站隔离及华为完整流程断言保持。

按仓库约定补充契约自测但不在本地运行构建或测试；提交推送后检查对应提交的现有 CI。没有 CI 时明确报告缺口，原业务用例由用户在实际对接环境手动回归。
