# 自动截图与用例报告

## 已确认需求

业务截图由每条用例控制：用例决定拍摄时机、画面及其证明的业务现象，并通过 `capture(name, description=..., expected=..., actual=...)` 提供说明。框架统一保存截图、关联步骤、防止覆盖并生成每条用例报告，同时在失败时尽可能保存现场。每张截图需要说明图片含义、预期现象、实际现象和拍摄时判定。

## 行为与边界

- 用例在关键业务画面调用 `capture()`，可保存零张、一张或多张截图；通过、跳过及停止时不强制生成结束截图。没有主动截图的通过用例仍生成完整报告，截图列表为空。
- 步骤异常时及时保留失败现场；step 外断言失败和准备失败由 pytest 在清理前兜底截图。清理失败也记录现场，驱动已经关闭时明确说明无法截图，不重开应用补拍。
- 界面执行、旧演示入口和直接运行 pytest 共用自动注册的报告插件，无需在用例中加载或调用报告输出。
- 每条已执行用例自动生成 report.json 和 report.md，包含用例名称、步骤、预期/实际、最终状态、错误和截图说明。准备阶段失败、跳过和清理失败也生成报告，不因没有 desktop fixture 而遗漏。
- 用例提供的截图说明、预期和实际优先；未显式提供时仅关联当前步骤或最近步骤，不汇总无关检查冒充当前画面。图片不用于自动识图判定。未提供的业务预期/实际明确标注未提供，不编造现象。步骤通过不等于整条用例通过，截图记录拍摄时的判定，最终报告以 pytest 全阶段结果为准。
- 驱动尚未建立、应用已退出或截图保存失败时，报告记录证据缺失原因；保留业务测试原始结果与错误，不以证据缺失掩盖失败。
- 多张截图使用不同文件名，不覆盖最初失败现场；重复结束或关闭不重复生成相同失败记录。框架自动截图标注“失败现场”，与用例业务截图区分。
- 当前详情、历史详情和图片预览均展示截图说明；旧报告没有说明时标注旧记录未提供。
- 不修改被测 DSP 系统、不改变业务断言、不运行依赖账号和设备的业务测试。本轮仅运行框架自测与前端检查。

## 验收

1. 不调用 capture 或报告输出的通过用例，自动得到独立 JSON/Markdown 报告，不拍摄结束截图。主动截图完整保留用例提供的说明、预期和实际，结束时不额外补拍。
2. step 外普通断言失败也在清理前截图；保留最初步骤失败图，后续截图不覆盖。
3. 准备失败、跳过、停止、清理失败与无桌面实例时均保留正确报告状态；仅失败兜底尝试截图，无法截图明确给出原因。
4. 截图包含 description、expected、actual、status、capture_status、error、time；在报告及界面展示，缺少结构化现象时明确提示。
5. 框架自测验证通过、失败、截图失败、清理失败、提前关闭和重复关闭，现有失败用例与业务预期保持原样。
