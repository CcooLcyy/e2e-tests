# 第三方 104 主站接入基础

## 已确认范围

继续使用 ProIEC104Client，测试上位机增加可选环境配置、只读主站检查、原生窗口会话和双端证据汇总。具体业务用例及操作顺序由用户后续提供，本次不新增业务用例，不自动连接、总召、遥控、遥调、修改主站配置或关闭主站。

## 环境与实例归属

- 主站默认不启用；旧环境缺少字段时保持原行为。
- 保存启用开关、程序路径、原生后端（win32/uia）、等待秒数。首版仅接管已打开的实例，不启动或结束主站。
- “检查主站”使用当前填写的参数，独立于 DSP 上位机路径和 EdgeDriver 校验；检查不修改目标窗口或协议连接。
- 根据完整程序路径及主窗口筛选唯一实例，多个实例或无实例明确报错；记录 PID、窗口句柄和程序路径，后续操作重新核对归属。
- 依赖缺失、非 Windows、窗口无响应、读取超时都明确报告，不返回伪造的连接状态。配置了目标窗口不代表与 DSP 已连接。

## 原生会话

- Python 驱动独立于 Selenium，按需由 master104 fixture 创建；既有用例无需接入主站。
- 使用独立辅助进程执行原生窗口读取与截图，父进程执行截止时间和停止检查；超时仅终止本次辅助进程，保留主站。
- 提供接管、结构化窗口快照、步骤记录、检查、截图和会话释放。快照注明采集时间、目标身份和控件信息；不将空树解释为成功数据。
- 原生截图独立命名，截图失败明确保留缺失原因；不使用 DSP 上位机截图替代主站截图。首版不提供原生截图自动标注。
- 不缓存旧的控件序号充当稳定定位，不在失败时重发协议命令；具体操作待用户确定后扩展。

## 双端证据

- 一个用例可同时注册 DSP 上位机及主站会话。保留各来源原始步骤编号和截图，最终报告将来源及步骤关联唯一化，避免相互覆盖。
- 既有单 DSP 会话的编号、截图和判定保持兼容；新增主站现场须在步骤、截图、元信息中标明来源。
- 原始业务异常、主站采集错误、环境前置条件失败分别保留；不将一次恢复后的成功覆盖原始失败。
- 共用原有停止标记和任务环境快照；停止后仅释放本次测试拥有的资源。

## 验收与验证边界

框架自测覆盖旧环境兼容、字段校验、检查与任务互斥、无/多实例、辅助进程超时取消、双端报告无覆盖、步骤与截图来源关联，以及既有单会话兼容。自测使用替身，不连接 DSP 或操作真实主站。
