# AGC 增减闭锁端到端验收

## 已确认的预期与边界

本组验证当前有效下发设定值到限产生的闭锁遥信：到上限置增闭锁，到下限置减闭锁，回到区间内部解除；无需实际出力到限，不历史锁存。默认示例范围为 10～100 kW，中间目标为 50 kW。

测试工程与被测系统独立推进。失败必须保留失败、观察记录及两端截图，继续以已确认的固定预期判定。本地 Windows 验收由用户按需执行。

## 专用测试环境

- 使用专用的单成员 AGC 控制组，成员允许控制，绝对值有功目标、kW 单位、倍率 1、偏移 0，有效范围 10～100 kW；关闭自动参数调试，运行控制组功能，投入 AGC 并允许远方。
- 准备运行中的 DataCenter、AGC、IEC104 及单成员的采集/控制链路，配置主站遥调到 AGC 总目标及 AGC 增减闭锁到两个独立单点遥信的路由。不能使用 IEC104“无路由模拟数据”替代 AGC 输入。
- 准备支持测试会话和短浮点遥调的新版 `Msk104Master.exe`、WebView2 Runtime 及匹配的 `msedgedriver.exe`，以 Windows 普通权限运行。用例启动独立主站副本并通过界面连接专用下位机，收到 STARTDT 确认后总召。其他主站会话独立运行。
- 将 [验收配置示例](examples/agc-direction-block.json) 复制为 `local/agc-direction-block.json`，填写实际测试 IP、ModuleManager 端口、104 端口、组名、成员名、组连接 ID、公共地址及三个 IOA；示例的 `192.0.2.1` 是文档地址，不能直接运行。组名必须以 `e2e-agc-` 开头，连接 ID 从上位机实际组列表读取。配置中的边界是预先确认的固定期望，不会按被测系统实际值自动修改。
- 主站遥调点须为 `C_SE_NC_1` 短浮点、单点直接执行；AGC 总目标入口采用绝对值 kW。主站两个遥信 IOA 必须事先存在且有完整有效初值（可在准备环境时先给专用组中间目标并确认通信）。缺少初值、依赖、路由或专用配置时，用例在前置阶段失败，不会补建点表或猜测地址。
- 专用组必须已有一次合法成功下发及有效量测，测试上位机首先只读核对这些条件。主站总召终止后核对两个单点遥信初值。发送目标时在“遥调”页填写 IOA 和 kW 目标，观察时从“遥信”页核对公共地址和 IOA。
- 在测试上位机启用 104 主站并选择主站程序。用例要求主站会话处于数据传输已启动且显示未暂停状态。
- 为“实测未到限”场景保持测试成员实测在范围内部（示例 20 kW），同时允许接收上限设定值。如果实测已到上限，该前置条件不成立，必须报告失败，不改用普通到限场景充数。

## 固定验收场景

| 场景 | 独立准备 | 目标操作 | 必须满足 |
| --- | --- | --- | --- |
| 上限置增闭锁 | 先设 50，确认两个闭锁 false/GOOD | 设 100 | 成员已发布设定为 100，增闭锁 true/GOOD，减闭锁 false/GOOD；主站对应增闭锁点收到更新 |
| 增闭锁解除 | 先设 100，确认增闭锁 true/GOOD | 设 50 | 成员已发布设定为 50，增闭锁 false/GOOD；主站对应增闭锁点收到解除更新 |
| 下限置减闭锁 | 先设 50，确认两个闭锁 false/GOOD | 设 10 | 成员已发布设定为 10，减闭锁 true/GOOD，增闭锁 false/GOOD；主站对应减闭锁点收到更新 |
| 减闭锁解除 | 先设 10，确认减闭锁 true/GOOD | 设 50 | 成员已发布设定为 50，减闭锁 false/GOOD；主站对应减闭锁点收到解除更新 |
| 实测未到限仍置位 | 先设 50，实测有效且严格在上下限内部 | 设 100 | 同一轮最终观察中成员设定为 100、实测仍小于 100 且质量有效，增闭锁 true/GOOD；主站收到相应新遥信 |

## 新数据与证据

- 每次业务操作前记录同一主站实例中目标 IOA 的当前值、品质和接收帧序号。变位点必须匹配预期值，接收帧序号须同时晚于该点基线和本轮遥调发送帧，接收时间不得早于本轮发送时间。
- 无变化的伴随闭锁点只要求当前值和有效品质正确。
- 实测滞后专项必须取得发送本轮上限目标后的新量测。量测时间晚于准备阶段，且不早于本轮发送动作时间所在秒。两端时钟须同步。未来时间超过本机 1 秒、只有旧 GOOD 缓存或新量测已经到上限时都不能通过。AGC 页面单纯“数据陈旧”的展示提示不替代上述业务时间规则。
- 遥信质量必须明确有效、当前值、未被取代且未封锁；未知、无效、非当前、被取代或封锁均不能通过。窗口读取不完整、地址重复、列缺失、连接中断或时间无法解析时明确失败。
- 主站、DSP 上位机分别保留步骤、固定期望、原始观察和截图；上位机默认点表没有逐点质量列，不能把“是/否”直接当作 GOOD。用例展开 AGC 功率总览的“查看点值明细”，从同一组读取成员设定、实测以及两个闭锁的值、质量与时间，再与主站观察对照。
- 超时只继续只读观察至截止时间，不重发遥调、不重启模块、不切断/重连主站。失败先保存现场，再按正常资源归属释放本例会话；不得在失败后自动下发“恢复目标”覆盖现场。

## 操作与运行

用例通过 EdgeDriver 点击 `Msk104Master` 的遥调入口，向专用下位机发送真实的 IEC104 命令，再读取两端界面结果。

1. 准备上面的专用链路与配置文件，确认下位机版本已包含增减闭锁默认点，上位机版本支持功率总览和运行点值明细。
2. 测试环境选择全新独立副本，填写 DSP 上位机及 EdgeDriver 路径，启用 104 主站并选择支持测试会话的新版 `Msk104Master.exe`。可先用“检查主站”确认 EdgeDriver 能读取界面。
3. 刷新用例，选择末尾“AGC 增减闭锁”组的五项用例执行。各项独立先准备中间值或边界值，不依赖上一项执行结果。
4. 查看任务原有报告、`agc-direction-profile.json`、`agc-direction-observations.json`、主站遥调证据和两端截图。每个目标仅发送一次；暂停、取消、超时或失败后不自动恢复目标，保留最后现场。

## 遥调协议与验收

使用 `C_SE_NC_1`（类型 50）短浮点设值，传送原因为激活（6），使用直接执行。固定目标须可由 32 位浮点精确表示，示例 10/50/100 符合。主站的协议确认须对应本次公共地址、IOA 和设定值。协议确认后继续核对 DSP 成员设定值及闭锁遥信的业务结果。

端到端验收以 Windows 桌面用例的实际执行结果及双端证据为准。
