# 按需构建启动器

用户双击 CMD 后：检测 → 必要时更新 Node 依赖并构建 → 成功后打开 Release。

## 判定

对 frontend/、src-tauri/（排除 target/gen）、package.json/package-lock.json、vite.config.*、tsconfig*.json、Cargo 工具链和本地 .cargo 配置计算内容摘要。Python 用例、Python 内核、文档、local/artifacts 等不触发编译。
成功构建记录 local/desktop-build.json，包含源文件摘要、Release 路径与文件摘要、依赖摘要。缺少记录或输出、内容变化、构建中源码再次变化时不能当作最新产物。首次使用会保守构建一次建立基线。
只改变文件时间不触发构建。Node 依赖缺失或 package/lock 摘要变化时执行 npm ci；没有锁文件则 npm install。每次真正构建调用 npm run desktop:build，由现有 beforeBuildCommand 完成前端与 Rust 的正确构建。构建子进程固定 CARGO_TARGET_DIR 为仓库 src-tauri/target，使用宿主机目标，避免全局交叉编译环境变量使输出位置改变。

## 运行与失败

CMD 使用控制台 Python 显示构建过程，失败暂停保留原因及日志，不启动旧程序。Pythonw 调用时通过中文错误对话框提示。
已有 Release 正在运行时若需要构建，提示先关闭测试上位机；不自动终止用户窗口。无构建需求允许直接启动。
使用本机文件锁避免双击并发构建；失败或源码变化不更新成功标记。构建后只在源摘要与构建前一致时记为成功；输出不存在同样失败。
不自动安装系统编译器，也不修改全局配置。日志和标记仅放入忽略的 local/。

## 验收

- 缺少输出/标记或源文件增删改会构建；源码无变化直接运行。
- Python 修改不触发编译，源文件仅时间变化不触发编译。
- 构建失败、依赖失败、构建中改源码均拒绝启动旧程序。
- 成功后记录摘要；第二次启动无需 npm/cargo。
- 双击并发、旧 Release 占用时明确提示而不误杀。
- 定向单元测试、真实构建一次、再次检查不构建。
