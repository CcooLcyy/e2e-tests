# 测试上位机第一版

本文件记录第一版能力与最初 Tk 实现。当前默认界面已迁移到 React + Tauri，分层与通信约定见 [React-Tauri迁移](React-Tauri迁移.md)，用例与执行内核继续复用。

## 已确认范围

提供 Windows 桌面界面；用例全部用 Python 代码编写并自动发现；环境由用户搭建。
单任务顺序执行，灰色未执行、红色失败、绿色通过，当前项显示运行中。
环境可保存：上位机 exe、驱动、固定工作区或全新副本、配置基线、等待秒数、结束时关闭上位机。
每个用例单独保存步骤、预期/实际结果、耗时、截图；任务保存汇总和 JUnit 报告。
现有演示只验证登录页，不宣称覆盖登录或上下位机业务。

## 职责与接口

- `testbench/model.py`：Environment 数据模型、CaseInfo(id, name, description)；环境读写验证。
- `testbench/catalog.py`：discover_cases(root: Path) -> list[CaseInfo]。通过 pytest collect-only 收集真实 nodeid，不执行用例；错误必须展示。
- `testbench/controller.py`：TaskController(root: Path)。start(environment, case_ids) -> Path；poll() -> list[dict]；stop()；active 属性；run_dir 属性。单任务约束；所有耗时工作在独立工作进程，GUI 主线程只短轮询。
- `testbench/worker.py`：读取任务配置，降为普通权限，运行 pytest，通过插件输出 events.jsonl、summary.json。取消先创建 stop 标记，等待当前用例清理后不再执行后续；必要时只结束本任务进程树。
- `testbench/gui.py`：Tkinter/ttk 桌面界面，环境表单、全部用例和勾选、灰红绿圆点、实时步骤/详情、进度、历史记录、打开报告/截图。
- `start_gui.py`：GUI 入口；双击启动脚本调用本仓库 pythonw。

Environment 字段约定：name, app_path, driver_path, mode（fresh/workspace）, workspace_path, baseline_path, timeout（秒）, close_app（bool）。to_dict()/from_dict(data)/validate()；save_environment(path, env)、load_environment(path)。所有路径字符串。
CaseInfo 字段：id（pytest nodeid）, name（中文显示名，默认docstring首行）, description。
GUI 到后端不直接操作 Selenium。controller.start 不阻塞界面；其 poll 返回增量事件。
事件：`type` 为 task_started/case_started/case_finished/step/task_finished/error/log；用例事件含 case_id；case_finished 含 status（passed/failed/skipped/cancelled）、duration、message、artifacts_dir；step 含 name/status/expected/actual（可选）；task_finished 含 status/run_dir。错误必须显示为失败，不可假绿。

## 用例与隔离

业务用例存放 `tests/test_*.py`，仍兼容普通 pytest；内部框架测试存放 `selftests/`，不出现在产品用例列表。
每个用例使用 `artifacts/<任务>/cases/<唯一编号>/`，解决原 Demo 多用例目录冲突。
fresh 模式每次用例准备全新数据；workspace 模式复用专用工作区数据，按顺序重开同一工作区上位机。
workspace 不允许使用原安装目录，也不接管已有用户进程；需要保留测试实例时 close_app=false，后续重复启动必须检测并明确提示。
基线只复制非敏感初始配置，不自动复制缓存、用户凭据或既有系统配置。使用基线属于用户显式选择。
环境数据保存在忽略的 `local/` 中，不将本机配置、账号或产物入库。

## 验收

1. GUI 能显示自动发现的全部业务用例，增减 Python 用例无需修改 GUI。
2. 可保存并重载两种运行模式的环境；错误路径、非法超时、冲突工作区均阻止启动。
3. 实际运行两个独立业务用例，逐项灰→运行中→绿；失败项红，后续独立项继续。
4. 停止后未执行项保持灰色，任务明确已停止；退出界面时清理任务。
5. 实时显示步骤；每例有独立报告；历史任务可查看。
6. 在本机已有 Release 上实跑；内部自测验证发现、配置、失败及取消状态，不需要设备或平台凭据。

## 本轮实施分工

主代理负责文档、独立验收测试、集成与真实 GUI 验证；子代理分别负责执行内核和桌面界面。各自限定文件，集成后统一回归。
