# 业务报告与诊断资料

## 已确认范围

测试报告面向业务阅读，只显示测试目标、结果、预期与实际、关键截图及简短说明。完整技术细节必须保存，但不进入业务报告正文或默认详情界面。只修改测试上位机，不修改被测系统、业务断言或已有历史报告。

## 产物与关联

- 用例 `report.json` 继续保留完整元数据、步骤、截图记录、错误及阶段结果，原图、标注图、日志位置不变。
- 用例 `report.md` 为业务报告；新增 `diagnostics.md`，保存完整步骤、原始异常、阶段信息和全部截图索引。报告提供“诊断资料”入口，不内嵌诊断正文。
- 任务 `report.md` 使用统一生成器，显示任务时间、中文用例名称、通过/失败/已停止/未执行数量、耗时及用例报告链接；任务 `diagnostics.md` 提供完整任务快照、汇总、事件、日志和 JUnit 索引。
- 任务、用例及步骤编号保留在技术记录中供关联，正文不直接展示源码 nodeid、进程、端口、驱动版本、异常栈或内部对象。
- 业务报告不编造观察。缺少预期/实际时明确未记录；布尔检查翻译为“是/否”，不能据图片或标注推断业务通过。
- 失败摘要优先展示有明确业务预期与实际的失败步骤，避免只展示内层布尔断言。技术执行异常只给简短分类说明，详细原因进入诊断资料。
- 只选择关键业务截图用于正文，全部逐步证据仍保留在诊断资料。拍摄时步骤尚未结束的图只说明用于记录现场，最终判定以用例结果为准。
- 新版业务标注图使用 `annotation_format=business-v1` 区分，过滤图片页脚中的技术描述；旧标注图可能已烧入技术文字，默认业务视图使用其原图，旧副本仍在诊断资料中保留。无步骤编号的旧图不能误关联到另一条无编号检查。

## 展示接口

`testbench.reporting.business_case(result)` 返回独立业务视图：

```text
title: 中文用例名称
goal: 测试目标
result: 中文最终结果
summary: 简短业务结论
checks: [{step_id, name, status, expected, actual}]（可读字符串）
key_screenshots: [原图文件名]
```

原始记录保持原样。桥接增加 `business` 与 `diagnostics_path` 字段；执行详情和历史详情默认使用业务视图，原始步骤、错误和全部图片通过诊断入口查看。旧报告按读取时适配，不重写文件。

`write_task_report(directory, summary, task)` 由工作进程正常结束和控制器异常结束共用；不调用测试发现器或重跑用例，中文名称优先使用任务快照及已有用例记录。

## 停止处理

清理进程结束后，先读取尚未消费的结束事件及已生成的用例结果，再补齐中断/未执行项。已完成的失败结果、真实耗时、报告路径不能被通用停止记录覆盖。进程被强制结束但没有完整结果时，保留已存在的报告路径并明确任务已停止，不把未执行行为判为通过。汇总与界面事件使用一致的数据。

## 标注修正

账号信息标注仅定位工作台退出按钮相邻的账号区域，业务检查原有断言保持不变。编号放在框外优先，避免覆盖退出按钮文字；无法确认位置时只显示说明，原因保留在诊断资料。

## 验收与执行约束

先补充报告隔离、诊断完整性、停止结果合并及截图展示的自测用例，再实现。按当前仓库约定不主动执行本地构建、类型检查、静态检查或测试；本次仅做代码和 Git 差异审查，新增自测留待用户按需运行，不宣称验证通过。已有测试涉及旧报告结构的断言只迁移到完整诊断报告，业务判定断言不放宽。

建议用户验收：生成一批含通过、失败和中途停止的报告，确认正文无堆栈/源码/驱动载荷，诊断原记录完整、关键图片可切换原图、停止后已有结果和耗时不丢失。原先的错误密码明确提示要求保持不变。
