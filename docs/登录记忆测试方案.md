# 登录记忆与自动登录测试

## 范围与前置条件

通过真实 Release 窗口操作平台登录，验证程序关闭、重开后的可观察行为；无需连接下位机。使用专用测试账号和可访问的平台，账号密码仅从本机被忽略的配置读取。不得使用个人账号，也不得同时在其他实例使用该测试账号。

每项用例自动创建全新独立副本，即使测试环境选择了固定工作区。配置基线中的 `platform-login.json` 不会导入，账号必须可在所测 Release 默认的平台地址登录。

Windows 凭据按平台地址和规范化账号共享，复制 exe 或新建数据目录不能隔离凭据。每项用例开始前检查该精确凭据不存在；已有凭据时停止，不读取密码、不覆盖、不删除。进入守卫后，无论用例成功、失败还是正常响应停止，均清理该测试凭据。强制终止 Python 进程无法保证 finally 执行；下次运行发现残留时明确失败，由用户确认后手动清理。

## 用例与验收

| 用例 | 验收标准 |
| --- | --- |
| 不记住密码 | 两项均不勾选，成功登录后关闭重开，显示登录页且密码为空 |
| 仅记住密码 | 成功登录后重开，账号和密码回填，须点击登录才能进入工作台 |
| 自动登录 | 勾选自动登录，成功登录后重开，无需手动提交便进入正确账号的工作台 |
| 勾选联动 | 勾选自动登录时记住密码同时勾选；取消自动登录仍保留记住密码 |
| 取消记住密码 | 已保存密码后取消记住，自动登录同时取消，重开后密码为空 |
| 主动退出登录 | 工作台主动退出后重开，不自动登录，仍回填记住的密码 |
| 切换账号 | 已回填 A 的密码时将账号改为另一账号，密码清空，不串用 A 的密码 |

每项用例独立准备状态，不依赖上一项的执行顺序。重开必须终止原进程、等待退出后从相同副本及数据目录创建新进程，不能用刷新页面代替。进程清理失败时停止该项，不能带着旧进程继续验证。

每项结束时先关闭测试进程并确认退出，再删除精确测试凭据，避免仍在进行的登录请求重新写入密码。这组用例总是关闭窗口，不受环境中结束后保留窗口的选项影响。驱动的命令日志设为关闭，避免记录密码输入或回填响应。

## 证据与限制

报告保存步骤、预期与实际、截图和进程启动记录；密码匹配只记录布尔结果，不能将明文密码写进断言、事件或报告。截图保持密码遮蔽。Windows 凭据存在性可作为辅助检查，最终通过条件以界面及真实登录结果为准。

首批不覆盖不可达平台、无效凭据、服务端吊销等故障注入场景。框架自身回归使用测试替身，不代表真实桌面或设备验证。

重复执行重开测试会创建新的平台会话。关闭窗口不等于主动退出，凭据清理也不等于服务端会话撤销；本地平台源码限制每账号最多 16 个有效会话。若平台开始拒绝正确账号登录，应先确认测试账号会话容量及平台状态，由管理员处理测试账号的会话后再验收，测试不能自动清理其他会话或把登录失败改判为通过。
