# Modbus RTU 双端采集测试

五条基础 RTU 用例各自启动独立副本，在 DSP 上位机正常业务界面创建本例专用的 RTU 连接和点表，结束时清理本例创建的资源。

用例从「测试环境」给出的 slaveSim 入口读取现有配置，查找可恢复的手动 `0x03 UINT16 AB` 测试点。多站隔离选同一总线的两站，其他四条需要一站。缺少合适资源时，用例在不会重置其他运行设备的情况下创建专用总线。保存后从配置页和运行页读取实际总线、串口、站号和寄存器地址，并在上位机界面检查串口占用，再创建业务连接。DSP 上位机使用其已有在线业务入口。

分别单选每条用例，各从无本例连接和点表的状态连续运行两次。每次生成新的连接名和 Tag，正常结束后确认本次连接已从列表移除。如果保存操作后无法确认连接编号，报告待核对的连接名称并保留失败现场，供人工处理。

## 用例与固定验收值

| 用例 | 观察条件和期望 |
| --- | --- |
| 连接与点表保存后重读 | 在上位机创建并保存本例的 RTU 连接和点表，重新打开并读取，核对保存值和 slaveSim 上对应的设备、点位身份。 |
| 初始采集 | 在上位机独立创建并启动本例的 RTU 连接及点表。第一站原始值为 1234 时，上位机显示 1234、正常品质和有效采集时间。 |
| 变化跟随 | 第一站原始值先为 1234，随后为 2345。上位机两次值均匹配，后一次采集时间更新。 |
| 工程量换算 | 本例创建倍率 0.1、偏移 2 的点，原始值 1234 和 2345 分别对应上位机工程量 125.4 和 236.5，变化后采集时间更新。 |
| 多站隔离 | 两站初始值为 1234 和 4321，第一站变为 2345 时第二站仍为 4321，并确认两站采集继续更新。 |

用例自己设置并核对模拟初始值。变值用例先完成两端基线核对，再自己把第一站切换到 2345 并确认新值生效，然后核对上位机。模拟器设值失败和上位机采集失败分别记录。清理时恢复复用寄存器的原值，删除本例新建且身份仍可确认的总线。

默认采集时限为 300 秒，工程量绝对误差为 0.000001。记录总线、串口、站号、功能码、地址、Tag、倍率、偏移和两端观察。失败时先保留现场再清理。
