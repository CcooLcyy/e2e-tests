# Modbus RTU 双端采集测试

## 已确认范围

测试程序操作 DSP 上位机真实 Release 和 slaveSim 管理页面，分别读取两端实际结果，验证 RTU 采集闭环。Modbus TCP 使用独立分组，后续单独实现。本次只修改测试工程，不修改 DSP 上位机、下位机或模拟器，不自动执行本地构建或测试。

## 前置条件

- 用户准备可访问的平台、专用账号、在线下位机，以及已运行的 slaveSim；下位机与模拟器之间的本地串口或 PTY 已连接。本批使用本地串口传输，不覆盖 MQTT 透传。
- 执行时读取 slaveSim 配置，选择同一总线的两个适用自定义从站；不足时由用例通过页面补充，每站提供一个手动来源的 UINT16 / AB / readwrite 保持寄存器。用例通过管理页面设值，不通过 HTTP 接口或后台脚本代替页面操作与断言。
- 下位机的目标串口由本批用例独占，其他采集连接不得占用该串口。用例只新建、操作和删除有本次唯一名称的连接，不接管已有连接。
- 测试环境使用全新独立副本；专用账号放在被 Git 忽略的 `local/login-account.json`。环境页只填写下位机 ModuleManager 地址、轮询周期、采集等待时限以及当前 DSP 对接的 slaveSim 地址；具体总线、串口、站号和寄存器在执行时读取，不读取旧静态配置。完整规则见 [RTU运行时模拟器配置](RTU运行时模拟器配置.md)。
- Edge 浏览器及匹配的 msedgedriver 已由用户准备，模拟器使用本用例创建的独立浏览器会话。

## 首批用例与验收

1. 创建连接与点表：通过上位机页面新建专用 RTU 连接和 UINT16/0x03 点位，重新打开编辑页核对保存结果；同时读取模拟器对应寄存器身份和原始值。
2. 初始采集：模拟器页面设置原始值 1234 并核对显示；上位机启动该连接的轮询，在采集时限内显示 1234、正常质量和非空时间。
3. 变化跟随：先采集 1234，再通过模拟器页面改为 2345；两端分别核对新值，上位机时间须与前次不同。固定值来源和两次不同数值共同排除旧缓存通过。
4. 工程量换算：倍率 0.1、偏移 2，模拟器原始值 1234 时上位机必须为 125.4；改为 2345 后必须为 236.5，不能从上位机当前显示反推期望。
5. 多站隔离：同一总线两个站号分别为 1234 和 4321；只改变第一站至 2345，第一站更新，第二站仍为 4321。分别检查两端身份和值。

默认采集时限为 20 秒，数值绝对误差为 0.000001（无相对误差）；配置只用于明确环境和时限，不能改写上述固定测试期望。时间变化按页面可见精度判定，修改前等待页面时间粒度跨越。时间非空与质量本身不能替代数值断言。

## 隔离、清理和失败证据

每项用例自行登录并建立状态，不依赖前一用例。记录目标下位机、总线、串口、站号、功能码、地址、Tag、倍率、偏移和观察时间。两端截图均关联同一用例步骤，另存双端数值对照 JSON。

模拟器只允许修改手动来源测试寄存器并记录原值；结束时恢复原值，上位机停止并删除本例创建的连接，关闭本例浏览器。管理页不能撤销内部临时覆盖标记，因此只保证恢复原数值，不声称恢复该隐藏标记；这也是限定手动来源专用点的原因。停止请求后仍尝试清理本例资源。强制结束进程或设备失联时无法保证恢复，报告保留专用连接名称、原值及清理错误供人工处理。

失败先保留两端现场，再清理。前置条件不满足明确记录为前置失败；业务值、质量、更新时间或配置不符合预期保持失败。不得放宽断言、增加掩盖业务失败的重试或自动修复被测系统。页面等待只等待同一次操作的异步结果，不重复发送业务操作。

## 验证范围

框架自测针对配置边界、独立期望计算、过期时间和双端不一致，不代表真机业务通过。本机不自动执行测试或构建；本批真实业务由用户在测试上位机选择“Modbus RTU”分组执行，以报告和两端证据为准。仓库没有可用 CI 时明确报告验证缺口，不自动补建 CI 或回退本地验证。
