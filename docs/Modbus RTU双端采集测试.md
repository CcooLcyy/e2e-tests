# Modbus RTU 双端采集测试

每项用例可以单独运行。第一批仅将「连接与点表保存后重读」和「初始采集」迁移为在 DSP 上位机正常业务界面准备本例专用的 RTU 连接和点表，并在用例结束时清理本例创建的资源。变化跟随、工程量换算和多站隔离继续使用各自的预置连接与点表。

DSP 下位机服务、RTU 协议模块、串口、slaveSim 总线和设备及模拟初始值、变化工况均在运行前准备。用例在 slaveSim 只读取实际反馈。预置用例的环境和观察配置见 [RTU 模拟环境与观察配置](RTU运行时模拟器配置.md)。

保存重读和初始采集使用 [独立 RTU 配置示例](examples/modbus-rtu-independent.example.json)。复制到测试数据目录的 `local/modbus-rtu-independent.json`，填写专用下位机的现场直连地址、slaveSim 总线、下位机侧串口和单个从站的零基寄存器地址。下位机地址由用例填入 DSP 上位机连接界面。该串口须专供这两条用例使用，运行前在上位机确认没有既有连接占用它。专用设备的 RTU 模块全局 MQTT 配置也应提前初始化，因为现有 DSP 上位机打开 RTU 页面时会自动补写缺失的 MQTT 配置。建议选择「全新独立副本」。

分别单选两条用例，各从无本例连接和点表的状态连续运行两次。每次生成新的连接名和 Tag；正常结束后确认本次连接已从列表移除。如果保存操作后无法确认连接编号，报告待核对的连接名称并保留失败现场，供人工处理。

## 用例与固定验收值

| 用例 | 观察条件和期望 |
| --- | --- |
| 连接与点表保存后重读 | 在上位机创建并保存本例的 RTU 连接和点表，重新打开并读取，核对保存值和 slaveSim 上对应的设备、点位身份。 |
| 初始采集 | 在上位机独立创建并启动本例的 RTU 连接及点表。第一站原始值为 1234 时，上位机显示 1234、正常品质和有效采集时间。 |
| 变化跟随 | 第一站原始值先为 1234，随后为 2345。上位机两次值均匹配，后一次采集时间更新。 |
| 工程量换算 | 使用预置倍率 0.1、偏移 2 的点，原始值 1234 和 2345 分别对应上位机工程量 125.4 和 236.5，变化后采集时间更新。 |
| 多站隔离 | 两站初始值为 1234 和 4321，第一站变为 2345 时第二站仍为 4321，并确认两站采集继续更新。 |

测试前独立安排每项用例的模拟初始值和后续观测时序。初始值和后续值应分别保持到对应两端采样结束。业务步骤超时或未达到预期时保留失败和现场证据。外部环境缺失或脚本漏执行应有步骤时，记录对应原因和未执行的业务检查。

默认采集时限为 300 秒，工程量绝对误差为 0.000001。记录总线、串口、站号、功能码、地址、Tag、倍率、偏移和两端观察。失败时先保留现场再清理。使用预置资源的用例只关闭本次观察会话。
