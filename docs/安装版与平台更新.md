# Windows 安装版与平台更新

测试上位机提供 Windows x64 的当前用户安装版。安装包包含桌面界面、Python 运行时、测试内核和该版本的用例。安装或覆盖升级时，安装程序会检查本机 WebView2 Runtime，优先复用匹配的驱动缓存，缺少时通过 Selenium Manager 从微软下载。安装后在「测试环境」中选择被测上位机，已准备的系统 WebView2 驱动会自动填入。安装版使用与开发版相同的用例和配置格式。

驱动下载失败时，安装仍可完成。可联网后重新运行安装包，或在「测试环境 → 基础信息 → WebView2 驱动」手动选择匹配的 `msedgedriver.exe`。已手动保存的外部驱动路径会保留。

如果微软下载源明确返回当前系统版本没有匹配驱动，且软件指定的 Fixed Version 高于系统版本，安装器会准备私有 WebView2 和配套驱动。两项都就绪且驱动路径留空时，本次测试启动的 DSP 上位机副本会自动使用这份组合。系统 WebView2、测试上位机界面和 104 模拟主站继续用系统配置。断网、超时或版本无法确认时保留现有流程。

私有组合缓存在 `%LOCALAPPDATA%\com.mskdsp.testbench\.tools`，下载的 Runtime CAB 约 311 MB。首次准备需要联网和额外磁盘空间。私有 Runtime 随测试上位机维护版本。重新发布时更新 `testbench/webview_driver.py` 中的版本、微软 CAB 链接和 SHA-256，并核对配套驱动。

- 平台软件目录和应用内更新使用轻量包。电脑已有 WebView2 时直接复用，首次安装且缺少 WebView2 时从微软下载运行时。
- 如果现场断网且电脑缺少 WebView2，从对应的 GitHub Actions 发布运行下载 `testbench-windows-x64-nsis-offline-*` 产物并提前带到现场。离线包内含 WebView2 安装器，与同次运行的平台包版本一致，CI 产物保留 14 天。

## 检查与安装

1. 在右上角打开「版本与更新」，查看当前版本和更新通道，再点击「检查更新」。默认使用 Stable。需要提前试用构建时，主动切换到 CI，选择会随本机数据保留。
2. 有新版时查看版本和变更说明。测试任务、资源清理和连接检查结束后，保存环境配置，再点击「安装更新」。
3. 确认后，程序使用明文 gRPC 从平台下载安装包并验证签名。验签成功且内核完成退出后启动安装。重新打开后在右上角核对版本。

切换通道后只会提示版本号高于当前安装版本的更新。例如，从 Stable `0.1.0` 可以升级到 CI `0.1.1-ci.12.1`，切回 Stable 后会等到 `0.1.1` 或更高版本发布。

断网、下载失败或签名无效时，当前版本可继续使用。需要恢复时，可先关闭测试上位机，再使用保存的上一版安装包手动安装。已发布安装包也可从平台软件目录取得。

## 数据和旧工作区

安装版将环境配置和测试历史存放在当前 Windows 用户的数据目录 `%LOCALAPPDATA%\com.mskdsp.testbench`，更新时由安装程序替换程序文件。新任务会记录生成报告时的测试上位机版本。

从旧安装布局首次升级时会重新安装随包的 Python。后续覆盖安装会按内容指纹复用相同的 Python 运行时，每次完整替换测试内核和用例目录。安装详情中的 `Reusing the bundled Python runtime.` 表示已跳过 Python 写盘。

已有开发版工作区的电脑，可从「版本与更新」选择「导入旧工作区」，选择包含 `local` 和 `artifacts` 的原仓库目录。导入后检查被测程序、驱动、固定工作区和基线的路径，再开始运行。

## 首次分发验收

- 在没有源码仓库和外部 Python 的 Windows x64 电脑安装，打开界面并刷新用例，确认能正常收集用例。
- 在已安装 WebView2 的电脑上断网运行轻量包，确认可以安装并打开。缺少 WebView2 的电脑分别验证轻量包联网补装、离线包断网补装。
- 联网首次安装后确认测试环境自动填入匹配驱动，再断网覆盖安装确认复用缓存。清空驱动缓存后断网安装，确认仍能安装并手动选择驱动。
- 在微软下载源明确缺少匹配驱动的旧版本环境安装，核对 DSP 上位机测试副本使用私有版本，并核对系统 Runtime 和 104 主站配置。分别验证断网和 CAB 校验失败时不启用私有组合。
- 从旧工作区导入后确认环境和历史报告可读取，遇到同名配置或报告时保留安装版已有数据。
- 运行测试时检查新版，确认可查看版本，安装入口在运行及清理期间处于禁用状态。
- 确认首次打开默认选择 Stable。主动切换到 CI 后重启，确认选项保留且检查结果来自 CI。切回 Stable 后确认安装入口只对更高版本开放。
- 从旧安装版覆盖升级，确认用例能正常收集。再用 Python 指纹相同的包覆盖安装，确认详情显示复用、Python 文件写入时间保持不变，且旧版中已移除的用例文件消失。用 Python 指纹不同的包覆盖安装时，确认运行时会重新写入。
- 正常升级后核对程序版本、用例、环境配置及历史报告。分别验证断网、已是最新版和无效签名三种情况。
