# RTU 环境界面配置

## 已确认修复范围

前五项基础 RTU 用例和华为六路21台用例的环境参数统一在“测试环境 → Modbus RTU”填写，通过既有保存、导入和任务快照流程持久化到 `local/environment.json`。用例不再读取 `local/modbus-rtu.json`、`local/huawei-rtu.json`，不要求手工创建独立 JSON。

共享配置包括现场直连 ModuleManager 地址、波特率、轮询周期及采集等待时限。基础采集单独配置设备标识、模拟器总线、串口路径、两个站号与零基寄存器地址、数据位/校验/停止位及专用资源声明。华为机群单独配置六条共享串口路径及专用模拟器声明。管理页地址沿用既有 slaveSim 配置。

选择基础 RTU 用例时只要求基础参数完整；选择华为用例时只要求华为参数完整；同时选择两类则分别校验。两类均要求全新独立副本及有效模拟器地址。运行非 RTU 用例时不要求这些配置；旧环境文件无新字段仍可载入，未填完的参数可保存后继续编辑。

开始前在后端校验所选用例的参数，缺失或非法时向主界面返回具体中文错误，说明要到哪个环境分区补齐；校验失败不创建任务目录、不启动工作进程或业务页面。任务快照保存当次全部参数，执行阶段从快照读取，避免保存后再次读取不同的独立文件。专用资源声明默认不勾选，不猜测真实地址或串口路径。

本次只修复测试工具的环境入口与参数传递，原业务步骤、断言、工况、点表、排序、失败结果和截图证据不变。保留原始失败报告，不改为跳过或通过，不自动操作下位机或模拟器。旧独立 JSON 示例仅供历史格式参考，不再作为运行入口，也不静默迁移或删除已有文件。

## 验证与使用

补充保存与载入、旧配置兼容、嵌套默认隔离、不同选择下的参数校验、任务创建前拒绝和前端旧值回填自测。本地不主动运行构建或测试，差异审查后提交推送并检查该提交的 CI 可用性。

前端新增界面需要重新构建桌面程序。用户关闭旧测试上位机并再次运行根目录“启动测试上位机.cmd”时，现有启动器会按需构建更新；随后在环境界面填写保存，再手动运行原业务用例回归。不能仅刷新用例就宣称新界面已加载。

界面单次等待默认60秒，采集匹配仍使用独立的采集等待参数。总任务时限继续由单步等待时间、所选用例数计算；单独选择一个用例且界面等待为60秒时，总时限为720秒（12分钟）。未增加独立总时限设置，不能把环境配置修复视为完整机群执行已经验证。
